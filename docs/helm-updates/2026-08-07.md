## ⚠️ ArgoCD 9.5.14 → 10.3.0 — ArgoCD v2.x → v3.0 — PLEASE READ BEFORE MERGING

**This is the highest-risk update in this batch.** Chart version 10.x deploys ArgoCD v3.0. The self-managed ArgoCD (it manages itself) means a failed upgrade can take down the entire GitOps control plane.

**ArgoCD v3.0 Breaking Changes:**
1. **Repository configuration in `argocd-cm` removed.** Before v3.0, repositories could be configured in the `argocd-cm` ConfigMap. This is no longer supported — all repository credentials must be stored as `Secret` objects. If any repositories are still configured in argocd-cm, they will silently stop working after upgrade. Audit the argocd-cm ConfigMap before merging.
2. **Default resource exclusions changed.** ArgoCD 3.0 adds default exclusions for high-churn objects (Endpoints, EndpointSlices, Events, etc.). Apps that previously tracked these resources may show unexpected diffs.
3. **ApplicationSet nested selectors.** `spec.applyNestedSelectors` behavior changed for more intuitive filtering. Review any complex ApplicationSet definitions.

**Official upgrade docs:** https://argo-cd.readthedocs.io/en/stable/operator-manual/upgrading/2.14-3.0/

**Pre-merge checklist for argo-cd:**
- [ ] Verify all repository configurations are in Secrets (not argocd-cm)
- [ ] Check cluster has a recent etcd snapshot / ArgoCD export (`argocd admin export`)
- [ ] Plan for a brief control-plane disruption window during the Helm upgrade
