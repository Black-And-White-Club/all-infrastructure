### ⚠️ Breaking Changes in Applied Updates

#### argo-cd: 9.5.14 → 10.3.2 (MAJOR)

Chart major version 9→10. Known breaking changes in the 10.x series:
- If using `redis-ha`, a dependency update causes **selector label changes** that are immutable on the `argocd-redis-ha-haproxy` Deployment — this deployment must be deleted and recreated, not just patched.
- Default values were removed from `config.params` — review your `charts/argo-cd/values.yaml` for any keys that relied on removed defaults.
- VPA support added for all Argo CD components.
- `crd-project.yaml` renamed to `crd-appproject.yaml` to match upstream.
- Full changelog: https://github.com/argoproj/argo-helm/releases

#### cert-manager: v1.16.2 → v1.21.1

Upgrades across 5 minor versions (v1.17 through v1.21). Notable changes:

**v1.17:**
- Hash algorithm now selected based on RSA key length (3072-bit → SHA-384, 4096-bit → SHA-512).
- `NameConstraints` and `UseDomainQualifiedFinalizer` feature gates promoted to beta (enabled by default).

**v1.19:**
- Do NOT run v1.19.0 — there is a bug causing unnecessary certificate re-issuance. v1.21.1 already incorporates the fix.

**v1.21 — ⚠️ Potential Observability Break:**
- Helm values **`prometheus.servicemonitor.targetPort`**, **`prometheus.servicemonitor.path`**, and **`prometheus.podmonitor.path`** have been **removed**.
- The controller Service metrics port has been **renamed** from `tcp-prometheus-servicemonitor` to `http-metrics`.
- **Action required:** Check `charts/cert-manager/values.yaml` for these keys and any Prometheus scrape configs that target cert-manager's metrics endpoint. Update before merging.
- Full release notes: https://cert-manager.io/docs/releases/release-notes/release-notes-1.21/
